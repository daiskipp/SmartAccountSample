## Additional Notes

- **Current implementation (2026-08-24)**: The former Leptos SSR shell was removed.
  `src/app.rs` now exposes an Axum recovery API with an in-memory development store,
  or an optional SQLite-backed store when `RECOVERY_DATABASE_PATH` is configured:
  L4 commitment registration, short-lived signed proof challenges, distinct two-person
  approval gating, and short-lived opaque L2 pairing relay tokens. The 4-eyes
  approval endpoint can authenticate configured operator identities with bearer
  credentials; a production identity provider remains to be integrated. Smart-account-kit
  transaction integration is implemented for L1 backup signing, L2 paired
  passkey addition, and L3 guardian-rule installation plus multi-signer
  replacement-passkey submission. L4 setup creates a threshold-gated initiation
  rule, a delayed finalization rule, and a two-factor self-recovery rule so the
  operator cannot act alone and user two-factor recovery remains available.
  Once the wait is due, the browser reconstructs the phrase-derived and
  independent second-factor Ed25519 signers in memory and uses the finalization
  rule to add a replacement passkey; successful recovery keeps that passkey
  connected rather than leaving a temporary signer session active.
  `recovery-scope-policy` permits only Rule#0 signer mutations, or the one
  bound TimeDelay initiation call. `time-delay-policy` consumes only a due,
  context-hash-bound L4 proposal and exposes an account-level public pending
  lookup for the unauthenticated wait-status page. Both policies are tested locally
  but still require deployment and an independent audit before release.
  Public Testnet deployments for the account WASM and the verifier/recovery
  policies are recorded in `docs/dev/deployment/testnet.md`. The Axum gateway
  has also created and confirmed a synthetic-credential Testnet Smart Account
  through managed Channels. A confirmed deployment made from the explicitly
  configured Smart Account WASM hash is persisted as a relay wallet root and
  receives only the fixed recovery-management function allowlist, so account
  setup can continue without a gateway restart; any long-lived credential
  remains external operational configuration and is intentionally not stored
  here.
  `frontend/` is now a strict TypeScript
  React/Vite application with smart-account-kit 0.6.2 pinned in its lockfile. It
  includes the L1 one-time recovery-phrase screen and phrase-driven replacement-passkey
  recovery. Rule#0 is converted to a 1-of-N threshold before the phrase signer is
  added, so either the original passkey or phrase-derived signer can authorize recovery.
  The browser-only phrase implementation has tested encoding, checksum validation,
  NFKD normalization, HKDF-SHA-256, and deterministic Ed25519 public-key derivation.
  It also includes L4's browser-only 256-bit S
  generation, contract-bound HKDF proof-key derivation, commit generation, and
  account/contract/network/challenge-bound Ed25519 proof signatures. The L4 setup
  screen displays S once, posts only a public proof key plus its commit, then zeros S
  from the displayed material after successful registration.

- **Architecture decisions (2026-08-24)**: フロントはTypeScript + React + Viteでsmart-account-kitを直接利用する。L4はS非送信のchallenge署名方式と、operator開始・待機後のPolicy認可という二段階を採用する。既存accountのlocalnet復旧はVite HTTPS proxy経由の直接RPC、新規アカウント作成とTestnet提出はAxum gateway + OpenZeppelin Relayer Channelsで行う。localnet の Channels 用 API key と管理 secret は devcontainer の名前付きボリュームにのみ生成する。詳細は`docs/dev/plans/recovery/plan.md`。

- **Localnet automation (2026-08-25)**: `just localnet-bootstrap` はProtocol 27 localnetと連動するRelayer stateだけを再作成し、固定したOpenZeppelin `stellar-contracts` commitからSmart Account関連4契約とローカル2 policyを再ビルド・デプロイする。生成した公開設定は無視対象の`frontend/.env.local`、API用WASM allowlistは`.devcontainer/localnet.env`に保存する。デプロイヤー鍵は一時CLI設定に限定して完了時に破棄する。
