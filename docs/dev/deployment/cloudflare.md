# Cloudflare deployment (Testnet verification)

A second, Cloudflare-hosted deployment path exists purely for Testnet
verification — added at user request, not part of the recovery brief's scope.
It covers **L1--L3 only**; L4 is unwired from the app regardless of deployment
target (see the L4 note in `CLAUDE.md`).

`src/worker.rs` runs the same `app::router_with_state` Axum router inside a
Cloudflare Worker, with a single Durable Object (`RecoveryStore`, SQLite
storage backend, Workers Free plan-eligible) standing in for the native
build's optional SQLite file. It talks to OpenZeppelin's hosted Testnet
Channels service (`https://channels.openzeppelin.com/testnet`) instead of a
self-hosted Relayer, so no Redis/Relayer containers need to be deployed. Only
`src/app.rs`'s persistence (`AppState::persist`) and outbound Channels call
(`RelayGateway::send_to_channels`) differ per platform, behind
`#[cfg(target_arch = "wasm32")]`; every route, handler, and the `Store` itself
are unchanged and shared with the native binary.

This assumes a contract set is already deployed to Testnet — see
[`testnet.md`](testnet.md) if it isn't yet. `wrangler.toml`'s `[vars]` and the
frontend's `VITE_*` values must both point at that same deployment.

## One-time setup

```bash
cargo install worker-build --locked  # needs pkg-config/libssl-dev, provided by the devcontainer image
pnpm install                         # installs wrangler from the root package.json
pnpm wrangler login
```

Get a Channels Testnet API key from
`https://channels.openzeppelin.com/testnet/gen` (a one-time-display flow;
don't store it in plaintext).

## Configure `wrangler.toml`

Update `[vars]` with the contract set from `testnet.md`:

- `RELAY_WASM_HASHES` / `RELAY_MANAGED_ACCOUNT_WASM_HASHES` ← the Smart
  Account WASM hash.
- `RELAY_ALLOWED_ORIGIN` ← the Cloudflare Pages origin from the frontend
  deploy below (`https://<project-name>.pages.dev`). The project name can be
  chosen ahead of the first Pages deploy, so this can be filled in first.
- `RELAY_CHANNELS_URL` / `RELAY_NETWORK_PASSPHRASE` / `RELAY_WALLET_ROOTS`
  rarely change (`RELAY_WALLET_ROOTS` is smart-account-kit's fixed shared
  deployer address, the same on every network).

Set the Channels API key as a secret, never in `[vars]`:

```bash
pnpm wrangler secret put RELAY_CHANNELS_API_KEY
```

## Deploy the Worker

```bash
cargo check --target wasm32-unknown-unknown --lib  # type-check the Workers build
pnpm wrangler deploy
```

`wrangler deploy` runs `wrangler.toml`'s `[build].command`:
`CARGO_PROFILE_RELEASE_STRIP=false worker-build --release`, not plain
`worker-build --release`. Cargo's `strip = true` (in the workspace
`[profile.release]`, which otherwise shrinks the native binary) removes
custom sections `wasm-bindgen`'s release-mode codegen needs, and the build
fails with `externref table required for catch wrappers` without this
override; `worker-build`'s own `wasm-opt` pass already shrinks the wasm
output, so disabling Cargo's strip for this build costs nothing. Verified
locally: `cargo build --release` (native, strip on) and
`CARGO_PROFILE_RELEASE_STRIP=false worker-build --release` both succeed,
producing a ~1.4 MB `build/index_bg.wasm`. Do not remove that env var from
`wrangler.toml`'s build command.

Redeploying reuses the existing `RecoveryStore` Durable Object instance and
its persisted state; it isn't recreated per deploy.

## Deploy the frontend to Cloudflare Pages

Write the `VITE_*` values from `testnet.md` into `frontend/.env.production`,
**plus `VITE_SMART_ACCOUNT_RELAYER_URL` pointing at this Worker's `/api/relay`**
(e.g. `https://<worker-name>.<subdomain>.workers.dev/api/relay`, from the
`wrangler deploy` output above). This isn't generated by
`deploy-testnet-contracts.sh` — the Worker's URL is only known after it's
deployed — and without it the frontend's account-creation screen silently
stays unavailable (`hasRelayer()` in `frontend/src/smart-account/config.ts`
returns false), even though the rest of the site loads fine. Then:

```bash
pnpm --dir frontend build
```

Deploy `frontend/dist` to Cloudflare Pages under the project name used above:

```bash
pnpm wrangler pages project create <project-name> --production-branch main
pnpm wrangler pages deploy frontend/dist --project-name <project-name> --branch main
```

The `--branch main` on deploy matters: the root `<project-name>.pages.dev`
domain only serves the *production*-branch deployment (production branch is
whatever was set at project creation, `main` above). Deploying from any other
branch name only produces a preview URL, which won't match
`RELAY_ALLOWED_ORIGIN` and will be rejected by `/api/relay`'s CORS. The
origin must match `RELAY_ALLOWED_ORIGIN` exactly, including trailing-slash
presence.

## Verify

Same checks as `testnet.md`'s "Relay deployment verification", run through
the Worker instead of a local Axum process:

1. `GET /api/l4/status/:contract_id` (or any route) reaches the Worker.
2. A `smart-account-kit` account creation through `/api/relay` gets a
   Channels `confirmed` result, and the derived Smart Account is readable
   from Testnet RPC.
3. `stellar contract invoke --network testnet --id <time_delay_policy> --
   get_pending --account <G...> --rule <N>` returns `null` on a clean
   deployment.
4. Discard any temporary WebAuthn authenticator and Channels key used for the
   check.

## Redeploying the Worker without a new contract set

If only Axum code changed (no new Testnet contracts), skip `testnet.md` and
`wrangler.toml` edits — just:

```bash
cargo check --target wasm32-unknown-unknown --lib
pnpm wrangler deploy
```
